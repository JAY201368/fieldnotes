THE IDEA01 / 03

A note on the approach ↘

Keep the why
close to the work.

Software changes. The context behind it should stay easy to find.

This skill gives Codex a stage-based workflow: agree on an outcome, describe what each task must do, and carry evidence forward as work progresses.

It is designed for a main agent and focused subagents working from a shared understanding of the project.

✳

Plan in stages

Give each stage its own goal, requirements, task list, and acceptance records. Carry project architecture and decisions forward.

one chapter at a time
▧

Make tasks legible

Connect tasks to requirements. Describe behavior, boundaries, ownership, and how each outcome will be checked.

clear enough to hand off
✓

Keep useful evidence

Match verification to the risk of the change. Reuse evidence while it still applies and record why a check needs repeating.

check what matters
THE WORKFLOW02 / 03

follow the thread →

From the first brief
to the next chapter.

Each stage has a beginning, a working rhythm, and a deliberate handoff.

01
ALIGN

Agree on the stage

Define the goal, included requirements, and what completion looks like. Reuse the project's existing documents where appropriate.

✎
02
SHAPE

Make the work executable

Map requirements to task cards with observable acceptance criteria, dependencies, boundaries, and a verification plan.

▤
03
BUILD

Give each task a fresh worker

Choose a profile for the task. Independent work can run in parallel; the main agent owns integration and shared records.

↗
04
ACCEPT

Review the result and evidence

Check each criterion against the work and its evidence. Repeat checks when changes or a concrete risk make that necessary.

✓
05
HAND OFF

Close the stage with context

After confirmation, archive the stage and its handoff. The next stage begins with a fresh set of working documents.
